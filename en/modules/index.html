The modules

The base measurement C1 is the core of every cycle.

Beyond it there are modules that extend the measurement. A module runs separately, with its own access agreed in advance, and its findings land in the same report.

Every module can be purchased separately alongside the cluster health check module: a storage array assessment, an Ethernet switch configuration check, an out-of-band BMC read-out over Redfish, or as-built documentation of the whole environment.

CodeModuleWhat it measuresStatus
C1 Cluster HealthCheck Everything measurable from the cluster nodes themselves: operating system and cluster, virtualisation, S2D and Azure Local, server hardware, network and storage paths, event logs, and the management and backup layers. Base measurement
M1 Ethernet switches The switch configuration against what the hosts expect, plus the interface counters normalised on switch uptime. available **
M2 Fibre Channel switches Zoning, fabric layout, port status and path redundancy where storage runs over Fibre Channel. available **
M3 Storage array The array itself: firmware, pools, LUNs, host mappings and path layout, against what the hosts see on their side. available *
M4 Out-of-band BMC (Redfish) Hardware, firmware and BIOS settings over iDRAC, iLO or XClarity; also usable on a node that is not running at the time. available *
M5 Azure control plane (ARM) The Azure side of the cluster: resources, networks, policies, roles and registration status. available *
M6 Azure Migrate Per-VM migration readiness against what actually runs. Only together with M5. available *
M7 Performance chain analysis Host, switch and array counters on one timeline over an agreed measurement window. in development
M8 Data protection and management layers The assessment of backup and management, beyond the presence check in the base measurement. in development
M9 System documentation The layout of the environment as a standalone document, built from the measurement data. available **
M10 Interview findings A structured conversation with your administrators about what no measurement can show. available *
M11 Custom module A module we build for you on request, against a quote with a ceiling. on request
R1 Root cause analysis The reconstruction of an incident across the layers. Orderable separately, outside the cycle too. orderable separately
M13 Identity and AD Tier 0 Exposure of Tier 0 (Domain Controllers and other critical identity workloads) from this cluster. Off by default; runs only at your request. available *
M14 Performance baseline (fio/ntttcp) A repeatable load measurement with fio and ntttcp, only inside an agreed maintenance window. available **

** Available with named limitations: whatever the module cannot yet read in your situation is stated as a limitation in the report. In development means not yet deliverable; we do not sell ahead of that.
