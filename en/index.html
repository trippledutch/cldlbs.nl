The core service

Four checks. One continuous health cycle.

The first round establishes the technical baseline. Three follow-up measurements verify whether remediation actually worked and detect new configuration drift before it quietly becomes the new normal.

Not merely finding what is wrong, but proving that it improved — and that it stays improved.

Methodology

From raw configuration to a defensible finding.

The methodology is the core of ClusterTriage. Every finding must trace back to measured data, technical context, a relevant requirement or best practice, and an explicit risk assessment.

Measure

Read-only PowerShell inventory captures the current state of the cluster, hosts and relevant infrastructure.

measured state

Normalise

Versions, roles, topology and dependencies are put into context so equivalent things are compared.

environment context

Analyse

Measured values are checked against product requirements, Microsoft guidance and technically justified best practice.

expected state

Prioritise

Not every deviation matters equally. Impact, likelihood, dependencies and recoverability determine priority.

risk level

Remediate

Every relevant finding gets a concrete action and, where needed, the sequence in which dependencies should be addressed.

actionable remediation

Verify

The next measurement proves whether a change had the intended effect and exposes new drift.

delta + trend
